# 阶段 5：多 Agent 辅助

- 对应设计文档：第 20 章"阶段 5：多 Agent 辅助"，另涉及第 10、11、12、15、17 章。
- 阶段目标：建立 ModelProvider 适配层与 LangGraph 基础图，实现六个辅助 Agent，落地建议存储、反馈、运行追踪与失败恢复。Agent 只生成建议，不能改变正式业务状态（10.3 节）。

## T5.1 ModelProvider 适配层（Ollama 默认 + OpenAI 兼容）

- 状态：已完成

**目标**

按第 15 章建立模型调用抽象，默认接 Ollama，可切换 OpenAI 兼容 API。

**具体内容**

- 在 `infrastructure/models/` 定义 `ModelProvider` 接口；实现 Ollama Provider（默认，`OLLAMA_BASE_URL=http://host.docker.internal:11434`）与 OpenAI 兼容 Provider，由 `LLM_PROVIDER` 配置切换（15 章配置清单）。
- 可使用 LangChain 的模型适配包，但不与 Ollama 绑定；业务代码不能直接实例化具体模型客户端（15 章）。
- 模型只接收完成当前分析所需的最小上下文（16 节）；使用云端模型时，界面明确提示数据将发送至外部服务（16 节，前端提示随 T5.7 落地，本任务在配置层暴露"当前 Provider 是否为外部服务"标识）。
- 模型超时、不可用等错误统一封装，供上层按 17.3 节策略处理。

**依赖**

T1.2

**验收标准**

- `LLM_PROVIDER=ollama` 时可完成一次真实调用；切换为 OpenAI 兼容配置时代码零改动可用（可用 mock 服务验证）。
- 业务/Agent 代码中 grep 不到对具体模型客户端的直接实例化。
- 宿主机 Ollama 停止时，Provider 抛出统一封装的超时/不可用错误而非未处理异常。

## T5.2 agent_runs/agent_suggestions 表与 LangGraph 基础图

- 状态：已完成

**目标**

按 10.2 节搭建 LangGraph 基础流程，并用 PostgreSQL 持久化检查点与运行记录。

**具体内容**

- 建表：`agent_runs`（运行状态、模型、耗时、错误、触发来源）与 `agent_suggestions`（结构化建议、人工采纳结果、关联运行 ID），见第 11 章。
- 在 `app/agents/graphs/` 实现 10.2 节基础图：业务事件或人工请求 → 加载授权后的项目上下文 → 路由到所需辅助能力 → 结构校验与安全规则 → 保存 AgentSuggestion → 通知相关人员查看。
- LangGraph 检查点持久化到 PostgreSQL（17.3 节）；业务状态仍以 PostgreSQL 业务表为准，检查点不替代业务记录（原则 1）。
- Worker 进程承载图运行（4.2 节），API 通过 Redis 队列投递运行请求（复用 T1.6）。
- "通知相关人员查看"复用 T3.5 通知服务。

**依赖**

T1.6、T5.1

**验收标准**

- 人工触发一次分析后，`agent_runs` 出现对应运行记录，图在 PostgreSQL 中留下检查点。
- 运行完成后按 10.2 节生成建议记录并产生站内通知。
- 中断 Worker 后重启，可从检查点恢复或明确标记失败，不产生重复建议。

## T5.3 Agent 结构化输出 Schema 与权限护栏

- 状态：已完成

**目标**

按 10.2、10.3 节统一 Agent 输出结构，并从工具注册层面锁死 Agent 的写权限。

**具体内容**

- 在 `app/agents/schemas/` 定义统一 Pydantic 输出模型，至少包含：建议类型、建议内容和理由、使用的业务事实引用、置信度、风险和限制、模型、提示词版本和运行 ID（10.2 节）。
- 实现结构校验节点：输出解析失败时保存诊断信息，不保存为正式建议（17.3 节）。
- Agent 工具注册表只包含只读业务查询与"写入建议"两类工具；以下操作不注册为 Agent 工具（10.3 节）：创建正式工作项、修改负责人、审批转派、修改 DDL、通过审核、删除文件或业务记录、合并代码。
- 提供自动化护栏测试：遍历工具注册表断言不存在任何写业务命令的工具（第 22 章标准 10）。

**依赖**

T5.2

**验收标准**

- 模拟模型返回非法 JSON/缺字段输出时，系统保存诊断信息且不产生正式建议。
- 护栏测试通过：工具注册表中无业务写命令；Agent 运行全程未调用业务命令接口（可通过审计事件验证——Agent 运行不产生业务状态类审计事件）。

## T5.4 需求、分配与规划 Agent

- 状态：已完成

**目标**

实现 10.1 节前三个 Agent：Requirement Analyst、Assignment Advisor、Planning Advisor。

**具体内容**

- `app/agents/specialists/` 与 `app/agents/prompts/` 中实现：
  - **Requirement Analyst**：将自然语言需求整理为目标、约束、交付物和验收标准。
  - **Assignment Advisor**：根据能力（`member_capabilities`）、负载和历史交付推荐初始负责人及候选人。
  - **Planning Advisor**：建议工作项、协作点、DDL 和潜在风险。
- 三者挂入 T5.2 基础图的路由节点，输出统一走 T5.3 的 Schema 与校验。
- 对接人工触发入口 `POST /work-items/{id}/agent-analysis`（12.5 节）；创建工作项流程中"自然语言需求 → Agent 建议 → 人工确认"（13.1 节）由负责人在前端确认后才调用业务命令（原则 2）。
- 能力修正建议（6.2 节）以建议形式输出，不自动修改能力或权限。

**依赖**

T5.3

**验收标准**

- 输入一段自然语言需求，Requirement Analyst 产出符合 Schema 的建议并入库可查。
- Assignment Advisor 的建议包含候选人及理由，引用真实成员能力与负载数据。
- 负责人确认建议后才创建正式工作项；忽略建议时不产生任何业务写入。

## T5.5 风险、初审与总结 Agent

- 状态：已完成

**目标**

实现 10.1 节后三个 Agent：Workflow Risk Agent、Deliverable Review Agent、Summary Agent。

**具体内容**

- **Workflow Risk Agent**：识别逾期、阻塞、频繁转派和协作等待风险；由 Scheduler 周期触发（逾期风险扫描，4.2 节），也支持人工触发。
- **Deliverable Review Agent**：根据工作项验收标准对文本、文件元数据和 Git 提交说明进行初审，生成负责人审核清单；在提交审核（`IN_REVIEW`）时触发。注意：不读取与最小上下文无关的文件原文（16 节）。
- **Summary Agent**：生成项目进展、已完成事项、待审批和风险摘要，支撑日报、阶段总结和负责人汇总（4.2 节）。
- 初审与风险结果一律作为 `agent_suggestions` 保存并通知负责人，不触碰 `reviews`、`work_items` 等正式业务状态（原则 2、10.3 节）。

**依赖**

T5.3、T4.4

**验收标准**

- 构造一个临期/阻塞工作项，风险扫描后生成对应风险建议并通知负责人。
- 工作项提交审核后，负责人在建议中看到初审清单；`reviews` 表无 Agent 写入。
- Summary Agent 生成的摘要与数据库真实统计一致（抽查核对）。

## T5.6 Agent 失败恢复：指数退避重试与人工重新触发

- 状态：已完成

**目标**

按 17.3 节实现 Agent 运行失败的重试与人工恢复机制。

**具体内容**

- Agent 任务按指数退避重试；超过重试次数后 `agent_runs` 记录失败并允许人工重新触发（17.3 节）。
- 模型超时或不可用不回滚已成功的业务动作（17.3 节）；Agent 失败不影响核心工作流（第 22 章标准 9）。
- DDL 影响分析失败时按 8.4 节降级：`deadline_change_requests` 标记"未生成 AI 影响分析"，人工审批照常进行（与 T3.4 预留的状态对接）。
- 提供人工重新触发入口（复用 `POST /work-items/{id}/agent-analysis` 或对 `agent_runs` 的重试操作）。

**依赖**

T5.2

**验收标准**

- 模拟模型持续超时：观察到按指数间隔的重试，超过上限后运行标记为失败。
- Ollama 整体不可用时，登录、工作项、协作、审批等核心流程全部可用（标准 9）。
- 失败的运行可人工重新触发并成功完成。

## T5.7 Agent 建议 API、反馈与前端建议中心

- 状态：已完成

**目标**

按 12.5 节开放建议查询与反馈接口，按 13.1 节实现 Agent 建议中心。

**具体内容**

- 实现 `GET /agent-suggestions`（按类型、状态、关联对象过滤）、`POST /agent-suggestions/{id}/feedback`（采纳或忽略反馈，写入 `agent_suggestions` 的人工采纳结果）；`POST /work-items/{id}/agent-analysis` 已在 T5.4 对接，本任务补齐鉴权与错误处理。
- `features/agent-assistant`：建议中心页面——建议列表、理由、置信度、事实引用、采纳/忽略操作（13.1 节"Agent 建议中心"）；创建工作项时的"自然语言需求 → 建议 → 人工确认"引导流程。
- 使用云端模型时，界面明确提示数据将发送至外部服务（16 节，读取 T5.1 暴露的标识）。
- "Agent 分析完成"等 SSE 事件（4.3 节）触发建议中心自动刷新。

**依赖**

T5.4、T5.5、T3.6

**验收标准**

- 负责人可在建议中心查看全部建议并完成采纳/忽略，反馈结果入库。
- 采纳"创建/调整工作项"类建议时，由前端携带人工确认参数调用正式业务命令，Agent 不直接写业务表。
- 切换为 OpenAI 兼容 Provider 后，建议中心出现外部数据提示。
