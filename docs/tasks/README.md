- 日期：2026-07-26
- 来源设计文档：`docs/2026-07-26-agentos-workflow-platform-design.md`（下称"设计文档"）
- 组织方式：严格按照设计文档第 20 章"实施阶段"的六个阶段拆分

## 任务编号规则

- 任务编号格式：`T<阶段号>.<序号>`，例如 `T1.1`、`T3.4`。
- 阶段号对应设计文档第 20 章的六个阶段（1–6），序号在该阶段内从 1 递增。
- 每个阶段一个任务文档：`phase-<阶段号>-<名称>.md`。
- 任务粒度控制在 0.5–2 天可完成；依赖字段引用其他任务编号，跨阶段依赖同样使用完整编号。
- 范围约束：首版不做多项目、SSO、外部 API 集成、WebSocket、MinIO；Agent 只能生成建议，不能改变正式业务状态（设计文档 2.2、10.3 节）。任务内容不得超出设计文档范围。

## 关键里程碑（对应设计文档第 22 章 MVP 完成标准）

- **M1（阶段 2 完成）**：项目负责人能够创建成员和工作项（标准 1）。
- **M2（阶段 3 完成）**：转派申请与审批可用、历史负责人可查（标准 2）；成员可直接发起协作请求并完成产物回传（标准 3）；DDL 变更正确区分协作级与主任务级审批（标准 4）。
- **M3（阶段 4 完成）**：Git 链接、文本和文件能够版本化提交（标准 5）；负责人能够要求修改或最终通过（标准 6）；任意成员可查看全员工作量与任务摘要但不能越权下载无关交付文件（标准 13）。
- **M4（阶段 5 完成）**：Ollama 不可用时核心工作流仍可使用（标准 9）；Agent 不具备改变正式业务状态的工具（标准 10）。
- **M5（阶段 6 完成，即 MVP 完成）**：RAG 串行案例和双任务并行案例端到端运行（标准 7）；所有关键操作有不可覆盖的审计事件（标准 8）；Docker Compose 在 Debian 上启动全部应用服务（标准 11）；数据库和文件备份完成一次实际恢复（标准 12）。

## 任务状态说明

各阶段任务文档中的每个任务节点均包含一行"状态"字段，取值约定如下：

- **待开始**：任务尚未动工，所有任务初始状态均为"待开始"。
- **进行中**：任务已开始实现但尚未满足全部验收标准。
- **已完成**：任务的全部验收标准均已满足并通过验证。

状态变更直接编辑对应任务节点中的"状态"行，每次只改一处取值。
