- 阶段目标：补齐测试体系与端到端验收场景，落地备份恢复与安全核查，形成性能基线和内部发布文档，达成第 22 章 MVP 完成标准。

## T6.1 后端测试套件（单元/集成/并发/合约/审计）

- 状态：待开始

**目标**

按 18.1 节建立覆盖五个维度的后端测试体系。

**具体内容**

- 领域单元测试：工作项/协作请求/转派/DDL 四个状态机、权限策略、DDL 影响规则（7.4 节）和转派规则（7.3 节）。
- API 集成测试：基于 FastAPI + PostgreSQL + Redis + 文件存储的测试环境，覆盖第 12 章全部已实现的命令与查询接口。
- 并发测试：重复审批（转派/DDL）、乐观锁版本冲突、`Idempotency-Key` 重复请求只生效一次（17.2 节）。
- Agent 合约测试：结构化输出 Schema（10.2 节）、模型超时、输出解析失败（17.3 节），模型层用替身 Provider。
- 审计测试：断言每个关键动作（分配、转派、协作、回传、审核、DDL 变更、上传、下载）必须生成对应 `audit_events` 事件，且事件不可修改删除（18.1 节）。

**依赖**

T2.6、T3.4、T4.5、T5.7

**验收标准**

- 五类测试在 CI/本地一键运行并全部通过，关键状态机迁移覆盖率可统计。
- 并发测试稳定复现"只有一个请求生效"的语义，无偶发失败。
- 删除任一关键动作的审计写入，对应审计测试必失败。

## T6.3 RAG 串行端到端验收场景

- 状态：待开始

**目标**

按第 9 章 RAG 流程与 18.3 节要求，实现首个端到端验收案例（第 22 章标准 7 之一）。

**具体内容**

- 按第 9 章时序编排自动化场景：负责人分配 RAG 工作项 → 后端开发申请转派给 RAG 工程师 → 负责人审批通过（主责任转移）→ RAG 工程师向销售专家发起两次协作请求（整理资料、标注测试集）并收到回传 → 提交 Git 链接、评估结果和说明 → 负责人审核通过 → 勾选"已同步"并归档证据。
- 验证点（18.3 节）：每一步产生对应审计事件与通知；协作请求无需负责人审批、转派必须审批；历史负责人完整可查。
- 场景运行中开启 Agent：验证 Agent 建议生成但不改变正式业务状态（工作项/审批状态只由人操作变化）。

**依赖**

T6.1、T6.2

**验收标准**

- 场景脚本一键运行通过，全部验证点断言成功。
- 场景结束后可通过审计事件完整回放第 9 章时序，且无任何 Agent 造成的业务状态变更。

## T6.4 双任务并行端到端验收场景

- 状态：待开始

**目标**

按 18.3 节实现"RAG 与 Agent 工具设计并行执行"的验收案例（第 22 章标准 7 之二）。

**具体内容**

- 编排并行场景：负责人同时创建两个互不依赖的工作项（RAG 任务、Agent 工具设计任务），由不同成员推进，分别经历协作、提交和审核，不强制形成内部 DAG（第 9 章并行场景说明）。
- 验证点：两个工作项的状态、通知、审计事件互不串扰；同一成员的负载在看板中正确汇总；并行审批与幂等键语义正确。
- 同样验证审计事件、通知和 Agent 建议不会改变正式业务状态（18.3 节）。

**依赖**

T6.1、T6.2

**验收标准**

- 并行场景脚本一键运行通过；两个工作项独立完成且各自审计链完整。
- 看板/工作项列表在并行推进过程中展示的成员负载与真实数据一致。

## T6.5 备份与恢复脚本及恢复演练

- 状态：待开始

**目标**

按 19.4 节实现备份脚本与保留策略，并完成一次实际恢复演练（第 22 章标准 12）。

**具体内容**

- 在 `deploy/scripts/`（第 5 章结构）实现：
  - 每日 PostgreSQL 逻辑备份，输出到 `data/backups/`。
  - 每日上传目录（`data/uploads/`）增量备份。
  - 备份保留周期 14 天，超期自动清理。
- 备份任务由 scheduler 或宿主机定时任务触发，执行结果写日志。
- 编写恢复脚本与操作步骤，并执行一次真实恢复演练：在干净环境从备份恢复数据库与文件，校验业务数据与文件 SHA-256 完整。
- 保留演练记录（日期、耗时、校验结果），作为标准 12 的证据。

**依赖**

T1.1、T4.2

**验收标准**

- 备份脚本运行后 `data/backups/` 生成对应产物，14 天前的备份被自动清理。
- 恢复演练成功：恢复后的系统可登录、可查询历史工作项，随机抽查文件哈希与 `stored_files` 记录一致。

## T6.6 安全检查清单核查

- 状态：待开始

**目标**

对照第 16 章与 19.4 节逐条核查并修复安全问题。

**具体内容**

- 凭据与令牌：密码 Argon2 哈希、Refresh Token 哈希持久化可撤销、无公开注册入口（16 节）。
- 权限：抽查全部 API 用例显式执行项目角色和资源关系校验；文件下载权限（T4.3）；透明范围仅限任务摘要字段，无关成员不能查看交付文件正文、内部审核意见、令牌或敏感配置（16 节）。
- 日志与数据外发：日志不含密码、令牌、API Key、文件原文；模型只接收最小上下文；云端模型界面提示存在（16 节）。
- 网络面：数据库、Redis、Ollama 不对公网开放，正式内部部署只通过反向代理开放 Web 入口（19.4 节）；用端口扫描验证。
- 产出安全检查记录，发现的问题修复后回归 T6.1 相关测试。

**依赖**

T2.2、T4.3、T5.3

**验收标准**

- 检查清单逐条有通过/修复记录，无未处理的已知项。
- 端口扫描确认 postgres/redis/11434 仅内网可达。
