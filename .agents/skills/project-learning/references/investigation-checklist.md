# 项目调查清单

按需使用本清单。它是防遗漏的探针集合，不是要求逐项机械回答的问卷。

## 目标、领域与概念

- 项目的目标用户、核心问题、输入、输出和成功标准是什么？
- 系统有哪些参与者、用例、业务能力和外部系统？
- 哪些术语出现在类型、接口、数据模型、测试和用户文案中？同一概念是否存在多个名称？
- 核心实体、值对象、状态机、事件、不变量和生命周期是什么？
- 哪些规则属于业务约束，哪些只是当前技术实现？

优先证据：产品 README、示例、公开接口、领域模型、验收测试、错误信息。

## 技术栈与仓库形态

- 主要语言、运行时、框架、包管理器、构建器和代码生成工具是什么？
- 是单体、模块化单体、单仓多包、微服务、插件系统、库、CLI，还是混合形态？
- 哪些目录是手写源码、测试、基础设施、脚本、文档、生成物和 vendored code？
- 版本约束和环境差异在哪里声明？

优先证据：依赖清单、锁文件、workspace 配置、编译配置、容器文件、CI 工作流。

## 架构、边界与依赖

- 运行单元和部署单元有哪些？它们是否一致？
- 每个模块拥有什么行为和数据？公开入口是什么？
- 哪些依赖是编译期、运行期、数据层或运维层依赖？
- 依赖方向如何流动？是否存在循环、跨层调用或共享数据库耦合？
- 外部系统通过何种端口、适配器、客户端或事件接入？
- 哪些边界由类型、包导出、进程、网络、权限或数据所有权强制执行？

优先证据：入口文件、包导出、import 图、接口定义、依赖注入装配、部署清单。

## 启动、运行时与数据流

- 实际启动命令最终执行哪个入口？启动阶段按什么顺序加载配置、注册依赖、连接资源和启动监听？
- 主请求、命令、事件、定时任务和后台作业如何进入系统？
- 数据在边界处的形态是什么，经过哪些验证、转换、丰富、缓存和持久化？
- 事务、一致性、幂等、重试、超时、取消和资源清理在哪里处理？
- 优雅关闭如何发生？半初始化和失败启动如何恢复？

每条代表性路径使用如下结构记录：

```text
入口 -> 解析/验证 -> 编排 -> 领域决策 -> 状态变化 -> 外部 I/O -> 输出/事件
                     |                                   |
                     +---------- 错误与观测 ------------+
```

## 关键实现与契约

- 哪些类、函数或模块承载最多业务决策，而不是单纯转发？
- 哪些接口被多个实现或调用方依赖？
- 哪些配置项会改变行为、拓扑、安全或性能？默认值和覆盖优先级是什么？
- 核心数据结构如何序列化、校验、版本化和迁移？
- 哪些契约没有类型表达，只存在于调用顺序、命名、异常或测试中？

为关键符号记录：职责、输入输出、不变量、副作用、错误模式、直接调用方、测试和修改风险。

## 模式、实践与取舍

- 使用了哪些可由结构证明的模式，例如分层、六边形、CQRS、事件驱动、仓储、策略、插件或管道？
- 哪些模式只是命名相似，实际并未形成对应约束？
- 格式化、静态检查、代码生成、依赖约束和评审门禁如何执行？
- 当前设计优化了什么：交付速度、可替换性、一致性、吞吐、延迟、成本还是兼容性？代价是什么？

只有存在实现、测试、文档或历史证据时才命名设计模式和技术取舍。

## 测试与交付

- 单元、集成、契约、端到端和性能测试分别位于哪里，覆盖哪些边界？
- 测试如何创建夹具、隔离外部系统、管理时间和随机性？
- 本地命令与 CI 门禁是否一致？哪些检查是发布前独有的？
- 构建产物、镜像、迁移、部署、回滚和环境配置如何流转？
- 是否存在无法从仓库验证的外部发布步骤？

## 可观测性、安全与性能

- 日志、指标、追踪、审计、健康检查和告警分别覆盖什么？是否能关联一次完整请求或作业？
- 信任边界在哪里？认证、授权、输入验证、秘密管理和敏感数据脱敏如何实现？
- 关键性能预算是什么？缓存、批处理、并发、分页、连接池和背压在哪里实现？
- 有哪些明确测量数据，哪些只是代码层面的性能意图？

不要读取或输出秘密值；只确认变量名、引用点、来源类型和是否缺失。

## 隐含约定与历史包袱

- 是否有文档未声明但被测试、脚本或调用方共同依赖的命名、目录、初始化顺序或错误语义？
- 是否有兼容层、重复模型、废弃入口、临时开关、特殊部署分支或跨模块直连？
- 注释中的 TODO 是否仍然适用？提交历史是否能解释异常结构？
- 问题是当前仍有成本的包袱，还是合理的历史痕迹？

记录时使用：现象、当前成本、历史证据、不能直接移除的原因、尚待确认信息。没有历史证据时标记为推断。

## 安全调查边界

- 优先静态阅读和只读命令。
- 忽略生成物和第三方目录，除非它们直接影响运行契约。
- 不读取 `.env`、密钥、令牌、Cookie、私钥或凭据文件内容。
- 不因“理解项目”而自动安装依赖、启动长驻服务、连接远程环境、执行迁移或写入数据。
- Git 历史只用于回答具体疑问，避免无目标地遍历全部历史。
